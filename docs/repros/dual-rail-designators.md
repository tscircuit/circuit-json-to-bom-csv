# Dual Rail Power Indicator: ambiguous manufacturing designators

This is a reproduction-only change in circuit-json-to-bom-csv. No production implementation or dependencies are changed.

## Board

One 44 x 24 mm PCB uses two named instances of the same indicator channel. Rail5V contains a 1k resistor and green LED; Rail3V3 contains a 470 ohm resistor and blue LED. Both channels reuse local component names R1 and D1. Their source identities and source groups are distinct. A three-pin input supplies separate 5 V and 3.3 V rails with common ground.

All construction, routing, rendering, and exports ran locally. The final board has 5 electrical components, 6 routed PCB traces, and no core error elements. The full committed Circuit JSON validates against the exporter's pinned circuit-json 0.0.543 schema.

## Observed output

The actual bom.csv contains five component rows but only three distinct designators: J1, R1, D1, R1, D1. The two R1 rows have different resistor values, 1k and 470. An assembly consumer cannot use the Designator column to distinguish those physical parts.

The converter uses source_component.name without source-group ancestry. includeSourceIds preserves identity in programmatic BOM rows, but those IDs and the channel context are not serialized into manufacturing CSV. This report concerns the flat manufacturing CSV, not the hierarchical assembly-BOM API.

A correct export must provide unambiguous physical designators consistent with downstream placement data, or explicitly reject ambiguous input. Silently emitting collisions is the reproduced behavior. This PR does not prescribe a renaming convention.

## Reproduce locally

Run bun install, then bun test. The suite includes an independent observed-output CSV snapshot and an explicitly expected-failure uniqueness test. To expose the ordinary failure, temporarily replace test.failing with test in tests/dual-rail-designators-expected.test.ts and run that file. Expected distinct designators: 5; actual: 3.

The passing snapshot test checks five distinct source identities, two separate resistor source groups, different resistor values, no core error elements, and the actual exported CSV.

## Real evidence

Files in tests/assets/dual-rail-power-indicator:

- board.tsx.txt: exact TSX board source; stored as text so the exporter project does not need a new core/JSX dependency. Use this as board.tsx in a tscircuit project to rebuild it.
- board.circuit.json: unmodified output of the local core build.
- pcb.svg and pcb.png: actual circuit-to-svg output and its resvg rasterization.
- schematic.svg: actual schematic from the same Circuit JSON.
- bom.csv: actual output of this repository's unchanged exporter.

The text snapshot in tests/__snapshots__ is generated by Bun from the same CSV. No image-generation model, substitute drawing, mocked component IDs, or fabricated before/after evidence is used.
